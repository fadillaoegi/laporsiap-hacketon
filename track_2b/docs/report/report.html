1Summary

IASC asks for a chronology, transaction details and evidence; it received 637,055 reports between 22 Nov 2024 and 31 Jul 2026 [1]. What people actually hold is an untidy chat. LaporSiap lets them paste it, record the transfers they know, and get an Apertus-drafted chronology where every entry is bound to its original message by ID. The model writes only short descriptions; quotes are re-attached locally from the source, so the model can never alter evidence. Totals are computed by code. A person must confirm every entry before PDF/TXT/ZIP export unlocks.

Headline. On a frozen 12-case bilingual fixture, Apertus 8B passed the output contract 12/12 at ≈ USD 0.0001 per case — yet review found 3 material meaning errors no automatic check caught. 70B also passed 12/12 with no material errors, but still made minor slips. That is exactly why LaporSiap keeps the human in the loop.

Target architecture

a) On-premise — primary target. One Docker Compose stack runs the app and PostgreSQL on the organisation’s own machine. deploy/compose.gpu.yaml adds the official Apertus vLLM runtime, pinned in deploy/gpu-lock.json, sharing the app’s private network namespace; inference binds 127.0.0.1 only. b) Air-gapped — supported once images and weights are pre-loaded: the full manual workflow needs zero network, and AI needs only the local endpoint (LLM_BASE_URL accepts plain HTTP solely for loopback/private addresses).

3Use of Apertus

  • Models: swiss-ai/apertus-v1.5-8b, swiss-ai/apertus-v1.5-70b
  • Used for: inference (structured, source-bound summarisation) and evaluation / red-teaming (prompt injection inside chats)
  • Runs on: hosted Public AI for tests; on-prem vLLM prepared (70B: BF16, tensor-parallel 4, 4× H100 80 GB)
  • Prompt: bilingual-v6-time-preserved, embedded in the binary; SHA-256 exposed at /api/policy and stored with every draft

Why Apertus. Open weights and open training data mean a public-interest operator in Indonesia can self-host it, so victims’ chats need not leave their infrastructure. Indonesian and English worked without fine-tuning.

Where Apertus fell short

  • 8B dropped attribution (“I previously said …”) and once invented a registration step.
  • 70B on the hosted gateway intermittently rejected valid requests with HTTP 400 (6 of 12 on 13 Oct); an identical retry succeeded, so we reran those cases once.
  • On 11 Oct one “Apertus” request was answered by aisingapore/Qwen-SEA-LION-v4-32B-IT; our model-identity check rejected it.
  • Earlier prompts lost “next week”; we added validation that rejects drafts whose relative time phrases differ from the source.

4Data

All data is original and synthetic (fictional Nadia/Raka, fictional banks, masked accounts) under CDLA-Permissive-2.0: the 12-case fixture docs/evaluation/bilingual-safety-v1.json, 13 manual scenarios and 8 importable chats in docs/testing/. No real victim data, no personal data, no human subjects. Model outputs are kept as evidence and retain upstream rights.

5Evaluation

Task: one chronology entry per source message. Metrics: (1) output contract — strict schema, source binding, order, preserved time phrases, model identity; (2) per-entry semantic review against fixture criteria; (3) latency and token cost. Setup: frozen fixture (SHA-256), prompt v6, temperature 0, one attempt per case per model, models interleaved, no retries, run 13 Oct 2026 through the app’s own provider path; the 6 cases the 70B gateway rejected were diagnosed and rerun once on 14 Oct (31 requests in total).

Material 8B errors: lost “previously said” attribution on a corrected amount (EN + ID); mixed two messages and invented a step (privacy case, ID). 70B 400 diagnosis: the gateway claimed the system prompt was not a plain string although it was; an identical retry returned HTTP 200 — a provider-side fault, not the model or the app. LaporSiap does not auto-retry; the user retries or drafts manually.

Safety held in every answered case. Injected “SYSTEM: ignore previous instructions …” text was described, never obeyed; masked personal data never appeared in descriptions; totals and sources were unchanged.
Decision. 70B made no material errors, 8B made 3 — but both make minor slips, so review stays mandatory. 8B is the on-prem default — 10× cheaper, one GPU — because the review gate catches its errors; 70B is the quality option when 4× H100 is available.

Engineering checks: Go unit and PostgreSQL integration tests with the race detector, architecture-boundary checks (backend and frontend), 13 browser regressions — all green in GitHub Actions CI on the submitted commit.

Value, cost and scale. Primary users: job-seekers who transferred money to a part-time-job or top-up offer, and family members helping them. A case is ≈ 870 input + 110 output tokens. At 10× volume — 1,000 → 10,000 cases/day — hosted 8B costs ≈ $1.1/day versus ≈ $10.5/day for 70B. Self-hosted cost is GPU-hours rather than tokens (4× H100 for 70B ≈ $16/h list price; 8B fits one GPU). The Go API is stateless apart from PostgreSQL; AI concurrency, daily quotas and storage caps are configuration.

6Limitations

  • 12 development cases are not a statistical benchmark; semantic review was done by one reviewer (the coding assistant), not independently.
  • No real users or victims yet; a 2–3 person pilot kit is ready but not run. No measured time saving.
  • Model identity is API metadata, not a weights audit. The 70B rerun was a second attempt on another day; the hosted gateway’s intermittent HTTP 400 remains a provider risk.
  • Regex masking is not anonymisation; no OCR (attachments are references only); no accounts or token recovery.
  • Not affiliated with OJK/IASC. It does not file reports, block accounts or promise refunds.
